# 모바일 통합 분석 입력 설계

## 배경

현재 `signalmate-app`은 채팅 텍스트를 붙여넣고 네 가지 관계 상황 중 하나를 선택해 분석하는 최소 Expo 앱이다. 웹에는 채팅이 없어도 실제 만남 후기만으로 분석하는 흐름과 캡처 이미지 OCR API가 구현되어 있지만 모바일에는 연결되어 있지 않다.

이번 단계에서는 사용자가 가진 정보가 캡처, 채팅 텍스트, 실제 만남 후기 중 무엇이든 분석을 시작할 수 있게 한다. 여러 종류의 입력이 있으면 하나의 분석 자료로 합치며, OCR 결과는 사용자가 검수하고 개인정보를 치환한 뒤에만 분석에 사용한다.

## 목표

- 카카오톡 등 대화 캡처를 최대 20장까지 한 번에 선택한다.
- 이미지별 OCR 진행 상태를 보여주고 일부 실패가 전체 작업을 중단시키지 않게 한다.
- OCR 결과를 이미지별로 수정하고 개인정보를 일괄 치환한다.
- 채팅 텍스트와 실제 만남 후기를 단독 또는 함께 입력한다.
- 만남 후기만 입력한 경우에도 충분한 설명이 있으면 분석한다.
- 분석 결과에서 실제 만남 신호와 채팅 신호를 먼저 구분해 보여준다.
- 작성 중인 초안과 OCR 결과를 앱 재실행 뒤에도 복구한다.

## 이번 범위에서 제외하는 것

- 로그인과 계정 동기화
- 결제와 사용량 제한 화면
- 사람별 분석 기록 목록과 장기 타임라인
- 모델 학습용 사용자 피드백 및 라벨링 화면
- 원본 캡처 이미지의 서버 보관

## 선택한 접근

첫 화면에서 `캡처`, `텍스트`, `만남 후기` 중 하나를 주 입력으로 선택한다. 선택 이후에는 `정보 더하기`를 통해 다른 입력 종류를 같은 초안에 추가한다.

모든 입력란을 한 화면에 노출하는 방식은 모바일에서 길고 복잡해 제외했다. 완전한 단계별 설문 방식은 짧은 분석에도 화면 이동이 많아 제외했다. 입력 방식 선택형은 시작은 단순하게 유지하면서 복합 입력도 지원한다.

## 사용자 흐름

1. 앱 첫 화면에서 새 분석을 시작한다.
2. `캡처`, `텍스트`, `만남 후기` 중 주 입력을 선택한다.
3. 캡처를 선택했다면 최대 20장을 선택하고 순서를 조정하거나 삭제한다.
4. 이미지별 OCR을 실행하고 진행 상태와 실패 상태를 확인한다.
5. OCR 결과를 이미지별로 검수하고 개인정보 치환 규칙을 적용한다.
6. 필요하면 채팅 텍스트나 만남 후기를 추가한다.
7. 관계 단계, 만난 경로, 만남 분위기, 상대 적극성, 만남 후 연락, 원하는 도움을 선택하고 자유 메모를 입력한다.
8. 분석에 전달될 채팅과 상황 요약을 최종 확인한다.
9. 분석을 실행한다.
10. 실제 만남 신호와 채팅 신호, 종합 판단, 다음 행동, 추천 메시지를 확인한다.

## 화면 설계

### 1. 분석 시작

기존 설명 중심 홈 화면을 실제 분석 시작 화면으로 바꾼다. 상단에는 짧은 제목과 현재 초안 복구 여부만 표시하고, 본문에는 `캡처`, `텍스트`, `만남 후기` 세 가지 선택 컨트롤을 둔다.

- 캡처: 사진 선택기를 열고 최대 20장을 선택한다.
- 텍스트: 대화 내보내기 텍스트나 직접 정리한 대화를 붙여넣는다.
- 만남 후기: 가이드 선택과 자유 입력으로 바로 이동한다.
- 정보 더하기: 최초 입력 이후 다른 입력 종류를 같은 초안에 추가한다.

### 2. 캡처 선택과 OCR 진행

선택한 이미지를 작은 미리보기 목록으로 표시한다. 각 항목에는 순서, 파일 상태, 제거 버튼을 둔다. 긴 캡처가 이어지는 순서를 사용자가 바꿀 수 있어야 한다.

OCR 상태는 `대기`, `추출 중`, `완료`, `실패`로 구분한다. 전체 진행률과 완료 수를 표시하되, 실패한 이미지 때문에 성공한 결과를 버리지 않는다. 실패 항목에는 해당 항목 재시도와 삭제 명령을 제공한다.

### 3. OCR 검수와 개인정보 치환

이미지별 추출 텍스트를 편집할 수 있다. 이미지 미리보기와 추출 텍스트를 같은 항목에서 확인하며 다음 이미지로 이동할 수 있다.

치환 규칙은 `원문=치환값` 쌍으로 관리한다. 기본 예시는 `[내이름]`, `[상대이름]`, `[소개자]`, `[직장]`이며 사용자가 값을 직접 추가하거나 삭제할 수 있다. 규칙을 적용하기 전 변경될 위치 수를 보여주고, 적용 후에도 텍스트를 다시 편집할 수 있다.

연속 캡처 사이에 정규화된 동일 메시지가 반복되면 중복 후보로 표시한다. 자동으로 조용히 삭제하지 않고 사용자가 제외 여부를 확인하게 한다.

### 4. 상황과 만남 후기

모든 분석에서 API가 요구하는 관계 단계와 만난 경로를 먼저 선택한다. 실제 만남 후기는 짧은 선택 항목과 자유 입력을 함께 사용한다.

- 관계 단계: 첫 만남 전, 첫 만남 후, 두세 번 만남 후, 식어가는 느낌
- 만난 경로: 소개팅, 데이팅 앱, 지인 소개, 기타
- 입력 중심: 채팅 중심, 만남 후기 중심, 채팅과 만남 혼합, 만남 뒤 연락 중심
- 만남 횟수: 없음, 1번, 2~3번, 4번 이상
- 분위기: 어색함, 보통, 좋았음, 아주 좋았음
- 상대 적극성: 낮음, 보통, 높음, 판단 어려움
- 만남 뒤 연락: 없음, 내가 먼저, 상대가 먼저, 느려짐, 이어지는 중, 해당 없음
- 원하는 도움: 다음 메시지, 다음 만남 제안, 기다릴지 연락할지, 관계 정리 여부
- 자유 입력: 실제로 관찰한 행동과 사용자가 느낀 점

선택값은 웹의 `GuidedAnswers` 계약에 맞춰 전송한다. `원하는 도움`은 API의 필수 `userGoal`에도 다음처럼 대응한다.

- 다음 메시지 → `continue_chat`
- 다음 만남 제안 → `ask_for_date`
- 기다릴지 연락할지 → `evaluate_interest`
- 관계 정리 여부 → `decide_to_stop`

자유 입력은 2,000자 이내로 제한하고, 상황만으로 분석할 때는 의미 있는 설명 20자 이상을 요구한다.

### 5. 입력 요약

분석 직전 화면에서 다음 내용을 분리해 보여준다.

- 인식된 채팅 메시지 수와 발화자 구분 상태
- 실제 만남과 만남 후 연락 요약
- 적용된 개인정보 치환 규칙 수
- 제외된 중복 메시지 수

발화자를 구분하지 못했거나 상황 입력이 너무 짧은 경우 분석 버튼을 비활성화하고 수정할 위치를 안내한다.

### 6. 분석 결과

결과 화면은 사용자가 선택한 `분석 신호 우선` 구조를 사용한다.

1. 실제 만남 신호
2. 채팅 신호
3. 종합 판단
4. 추천하는 다음 행동
5. 추천 메시지와 복사 명령

실제 만남 신호와 채팅 신호는 긍정, 주의, 애매로 구분한다. 각 신호에는 판단 근거를 함께 표시한다. 종합 판단은 확정적 표현을 피하고 입력에서 확인된 근거와 불확실성을 함께 설명한다.

## 상태와 컴포넌트 경계

분석 초안은 화면별 로컬 상태로 흩어두지 않고 하나의 `AnalysisDraft`로 관리한다.

```ts
type AnalysisDraft = {
  primaryInput: "capture" | "text" | "meeting_note";
  images: ImageDraftItem[];
  pastedText: string;
  replacementRules: ReplacementRule[];
  relationshipStage: RelationshipStage;
  meetingChannel: MeetingChannel;
  guidedAnswers: GuidedAnswers;
  excludedDuplicateIds: string[];
  updatedAt: string;
};
```

주요 단위는 다음 책임만 가진다.

- `AnalysisDraftProvider`: 초안 갱신, 저장, 복구, 폐기
- `ImageBatchPicker`: 이미지 선택, 순서 변경, 삭제
- `OcrBatchController`: 최대 두 건 동시 OCR, 상태 전이, 재시도
- `OcrReviewEditor`: 추출 텍스트 수정과 이미지 이동
- `ReplacementRuleEditor`: 치환 미리보기와 일괄 적용
- `MeetingQuestionnaire`: 가이드 답변과 자유 입력
- `AnalysisInputSummary`: 분석 가능 여부와 최종 요청 미리보기
- `AnalysisResultView`: 신호 우선 결과 표시와 메시지 복사

OCR 병합, 중복 후보 탐지, 치환 적용, API 요청 생성은 순수 함수로 분리한다. 화면은 이 함수의 결과를 표시하고 사용자 명령을 전달하는 역할만 맡는다.

## 로컬 저장과 개인정보

- `AsyncStorage`에는 초안 메타데이터, OCR 결과, 편집된 텍스트, 치환 규칙, 가이드 답변을 저장한다.
- 선택 이미지는 분석 완료나 초안 폐기 전까지 앱 전용 캐시로 복사한다. 사용자가 개별 이미지를 삭제하면 해당 사본도 즉시 제거한다.
- 앱 재실행 시 저장되어 있던 `추출 중` 상태는 `대기` 상태로 되돌려 중단된 OCR을 사용자가 다시 시작할 수 있게 한다.
- 원본 이미지는 OCR 요청에만 사용하고 대화 분석 저장소에는 보관하지 않는다.
- 분석 서버에는 검수와 치환을 마친 텍스트 및 가이드 답변만 전달한다.
- 앱 로그에는 원문 대화, OCR 결과, 치환 전 개인정보를 기록하지 않는다.

## API 데이터 흐름

### 이미지 추출

각 이미지에 대해 `POST /api/v1/conversations/extract-from-image`를 호출한다. 클라이언트는 선택 순서를 유지하면서 최대 두 요청만 동시에 실행한다. 지원 형식과 파일 크기는 서버 계약을 따르며, 서버 오류 코드를 한국어 사용자 메시지로 변환한다.

### 대화 생성

검수 완료 후 `POST /api/v1/conversations`에 다음 정보를 전달한다.

- 병합한 채팅 원문과 파싱된 메시지
- `guidedAnswers`
- 관계 단계, 만남 경로, 사용자 목표
- 입력 출처와 임시 저장 모드

모바일 API 모듈은 성공 응답의 `data.conversation.id`를 읽고 필수 필드를 검증한다. 현재 앱처럼 응답 구조를 가정해 빈 식별자를 넘기지 않는다.

### 분석 실행

`POST /api/v1/conversations/{id}/analyses/stream`을 사용해 단계별 결과를 받는다. Expo 54에서 지원하는 스트리밍 방식으로 구현하고, SSE 줄이 네트워크 청크 중간에서 나뉘는 경우를 버퍼링한다. 완료 이벤트가 없거나 응답 형식이 잘못되면 빈 결과 화면으로 이동하지 않고 입력을 유지한 채 재시도를 제공한다.

분석 결과는 URL 매개변수에 JSON으로 넣지 않는다. 분석 세션 상태에 저장하고 결과 화면에는 분석 식별자만 전달한다.

## 오류 처리

- 이미지 선택 취소: 현재 초안을 유지한다.
- 지원하지 않는 이미지: 해당 파일만 제외하고 이유를 표시한다.
- 10MB 초과 이미지: 해당 파일만 표시하고 재선택을 안내한다.
- OCR 일부 실패: 성공 항목을 보존하고 실패 항목만 재시도한다.
- 네트워크 중단: 처리 상태를 실패로 바꾸고 입력과 OCR 결과를 유지한다.
- 발화자 인식 실패: 검수 화면에서 `나`와 `상대` 표시 형식을 안내한다.
- 상황 입력 부족: 자유 입력을 20자 이상 보완하도록 해당 필드로 이동한다.
- 분석 실패: 초안과 생성된 대화 식별자를 유지하고 분석만 다시 실행한다.
- 응답 검증 실패: 일반 오류로 감추지 않고 서버 응답 오류임을 기록하되 원문 대화는 로그에 남기지 않는다.

## 시각 및 상호작용 원칙

- 작업 화면답게 정보 밀도를 유지하고 장식용 카드나 큰 소개 영역을 사용하지 않는다.
- 선택 모드는 분할 컨트롤, 이진 설정은 토글, 이미지 작업은 아이콘 버튼을 사용한다.
- 아이콘은 `lucide-react-native`를 사용하고 익숙하지 않은 명령에는 접근성 레이블을 제공한다.
- 긍정은 녹색, 주의는 황색, 주요 명령은 짙은 중립색을 사용해 한 색상 계열에 치우치지 않는다.
- 동적 텍스트가 버튼과 상태 배지를 늘리거나 밀지 않도록 크기와 줄바꿈 규칙을 고정한다.
- 화면 읽기 도구, 글자 크기 확대, 최소 터치 영역 44pt를 지원한다.

## 테스트 전략

### 단위 테스트

- 선택 순서를 유지하는 OCR 큐와 동시 실행 수 2 제한
- 성공, 실패, 재시도 상태 전이
- 이미지별 텍스트 병합과 연속 캡처 중복 후보 탐지
- 치환 규칙 미리보기와 적용
- 채팅만, 상황만, 혼합 입력의 API 요청 생성
- 관계 단계, 만난 경로, 원하는 도움의 필수 API 값 대응
- 서버 성공 및 오류 응답 검증
- 분할된 SSE 청크 조립과 완료 이벤트 처리

### 컴포넌트 테스트

- 최대 20장 선택 제한과 순서 변경
- 일부 OCR 실패 후 다른 결과 보존
- 검수하지 않은 OCR 결과로 분석 진행 차단
- 만남 후기만 20자 이상 입력했을 때 진행 허용
- 입력 요약에서 메시지 수와 상황 요약 표시
- 관계 단계와 만난 경로를 선택하지 않았을 때 진행 차단
- 결과 화면에서 실제 만남 신호가 채팅 신호보다 먼저 표시
- 추천 메시지 복사

### 기기 검증

- iOS와 Android에서 다중 사진 선택
- 앱을 종료하고 다시 열었을 때 초안 복구
- 키보드가 자유 입력과 하단 명령을 가리지 않는지 확인
- 느린 네트워크에서 진행률과 재시도 동작 확인
- 긴 OCR 텍스트와 큰 글자 설정에서 겹침과 잘림 확인

## 완료 조건

- 사용자가 최대 20장의 캡처를 선택하고 순서대로 OCR할 수 있다.
- OCR 일부 실패가 전체 작업을 잃게 하지 않는다.
- 추출 텍스트를 수정하고 개인정보를 일괄 치환할 수 있다.
- 채팅, 만남 후기, 두 입력의 조합 모두 분석 요청으로 변환된다.
- 관계 단계, 만난 경로, 사용자 목표가 누락되지 않는다.
- 만남 후기만으로도 조건을 충족하면 분석 결과를 받는다.
- 앱 재실행 뒤 작성 중인 초안과 완료된 OCR 결과가 복구된다.
- 결과 화면은 실제 만남 신호와 채팅 신호를 먼저 구분해 보여준다.
- 테스트와 기기 검증에서 빈 결과 화면, 입력 손실, 원문 로그 노출이 발생하지 않는다.
