# 라벨 우선 관계 신호 평가 루프 설계

**날짜:** 2026-07-04  
**상태:** 설계 승인됨  
**목적:** 실제 대화 캡쳐에서 추출한 텍스트를 기반으로, 사용자의 블라인드 라벨과 SignalMate의 관계 신호 판단을 비교하며 호감 온도/신호 판정 성능을 점진적으로 개선한다.

## 배경

사용자는 실제 이성과 나눈 대화 예시를 활용해 모델 성능을 개선하고 싶다. 다만 이번 범위는 프로덕션 사용자 데이터 수집이나 모델 파인튜닝이 아니라, **개인 로컬 실험**이다.

이미 `landing-page-nextjs/learning/`에는 실제 캡쳐 기반 학습 트랙이 있다. 이 설계는 그 트랙을 대체하지 않고, "내 생각과 프로그램 판단을 비교해 정답률을 높인다"는 목표에 맞춰 평가 루프를 더 명확하게 정의한다.

## 결정된 범위

- 데이터 사용 범위: 개인 로컬 실험용.
- 이미지 처리 방식: 원본 캡쳐 이미지는 저장하지 않는다.
- 입력 방식: 앱의 기존 캡쳐 추출 API 또는 UI로 얻은 텍스트만 복사해 사용한다.
- 1차 개선 목표: 호감 온도와 관계 신호 판정.
- 성공 기준: 사용자의 블라인드 라벨과 프로그램 판단의 일치율을 측정하고, 불일치 케이스를 줄인다.

## 핵심 원칙

1. **원본 이미지 저장 금지**  
   캡쳐 파일은 repo, DB, 로그, 실험 폴더에 남기지 않는다. OCR 또는 Vision 추출 결과 텍스트만 임시로 확인한 뒤, 마스킹된 JSON으로 옮긴다.

2. **블라인드 라벨 우선**  
   시스템 결과를 보기 전에 사용자가 먼저 `temperature`, `topSignal`, `nextMove`를 기록한다. 그래야 프로그램이 사용자의 판단에 얼마나 가까운지 측정할 수 있다.

3. **불일치 중심 개선**  
   모든 케이스를 동시에 고치려 하지 않는다. 프로그램 판단과 사용자 라벨이 갈린 케이스만 모아 반복되는 오판 패턴을 찾는다.

4. **한 번에 한 변수만 변경**  
   개선할 때는 룰, 프롬프트, few-shot, 검색 파라미터 중 하나만 바꾼다. 그래야 before/after 차이가 무엇 때문인지 해석할 수 있다.

5. **정답률의 의미를 제한해서 쓴다**  
   여기서 정답은 객관적 진실이 아니라 "사용자의 블라인드 라벨과 일치했는가"다. 사용자의 라벨도 틀릴 수 있으므로, 큰 결론은 반복 케이스가 쌓인 뒤에만 낸다.

## 데이터 흐름

```text
실제 캡쳐
  -> 기존 이미지 추출 API/UI로 텍스트 추출
  -> 원본 이미지 폐기
  -> 식별정보 마스킹 및 일반화
  -> learning/captures/NNNN.json 작성
  -> 사용자 블라인드 라벨 작성
  -> learn:eval 실행
  -> 일치율/불일치 목록 확인
  -> 반복 오판 패턴 하나 선택
  -> 룰 또는 프롬프트 또는 few-shot 하나만 수정
  -> 같은 데이터셋으로 재측정
```

## 캡쳐 JSON

기존 `learning/lib/capture.ts`의 `Capture` 타입을 그대로 사용한다.

```jsonc
{
  "id": "0001",
  "source": "데이팅앱",
  "context": {
    "age_band": "20대 후반",
    "meeting_context": "소개팅 이후 초기 대화",
    "distance": "수도권 내 이동 가능 거리"
  },
  "relationshipStage": "early_chat",
  "meetingChannel": "dating_app",
  "userGoal": "build_rapport",
  "messages": [
    { "sender": "me", "text": "오늘 대화 재밌었어요 ㅎㅎ" },
    { "sender": "them", "text": "저도요! 다음에 또 얘기해요" }
  ],
  "myLabel": {
    "temperature": "warm",
    "topSignal": "상대가 다음 대화를 열어두는 표현을 했다",
    "nextMove": "가벼운 공통 관심사로 다음 대화를 이어간다"
  }
}
```

### 마스킹 규칙

- 이름, 연락처, SNS 핸들, 회사명, 학교명, 상세 지명, 얼굴/프로필 정보는 저장하지 않는다.
- 분석에 필요한 사회적 맥락은 넓은 범주로 일반화한다.
- 말투, 길이, 이모지, `ㅋㅋ`, 답장 흐름은 가능한 보존한다.
- 재식별 가능한 고유 사건은 일반화하거나 제거한다.

## 평가 방식

`learn:eval`은 1차로 각 캡쳐의 temperature를 비교한다. `topSignal`과 `nextMove`는 같은 캡쳐 파일에 기록하되, 초반에는 자동 점수화하지 않고 불일치 리뷰 메모로 사용한다.

- `myLabel.temperature` vs 시스템의 호감 온도 판단

1차 지표는 단순하게 유지한다.

- **temperature exact match:** `cold`, `neutral`, `warm`, `hot`이 같은지.
- **temperature distance:** 한 단계 차이인지, 두 단계 이상 차이인지.
- **disagreement list:** 왜 갈렸는지 사람이 읽고 기록할 수 있는 목록.

`topSignal`과 `nextMove`는 자유문이므로 자동 정답률보다 불일치 리뷰가 중요하다. 초반에는 사람이 직접 "동의/부분 동의/비동의"로 실험 카드에 기록한다.

## 개선 루프

1. 캡쳐 5~10개를 먼저 모은다.
2. 시스템 결과를 보기 전에 `myLabel`을 채운다.
3. `npm run learn:eval`을 실행한다.
4. 불일치 케이스를 읽고 반복 패턴을 하나 고른다.
5. 실험 카드에 가설을 쓴다.
6. 룰, 프롬프트, few-shot 중 하나만 바꾼다.
7. 같은 dataset으로 다시 `learn:eval`을 실행한다.
8. 일치율이 오른 케이스와 떨어진 케이스를 함께 기록한다.

## 접근법 비교

### 선택: 라벨 우선 평가 루프

가장 먼저 사용한다. 사용자의 목표가 "내 생각과 프로그램 판단 비교"이므로, 블라인드 라벨과 시스템 결과를 나란히 놓는 방식이 가장 직접적이다. 적은 수의 캡쳐로도 바로 학습이 시작된다.

### 보조: 트레이스 우선 해부 루프

불일치가 생겼을 때 원인을 찾는 용도로 사용한다. 룰 기반 피처, 임베딩 이웃, LLM 보정 중 어디서 판단이 틀어졌는지 확인한다. 모든 캡쳐에 매번 쓰면 속도가 느리므로, 대표 불일치 케이스에만 적용한다.

### 보류: few-shot 데이터셋 확장 루프

반복되는 패턴이 충분히 쌓인 뒤에만 사용한다. 표본이 적을 때 실제 사례를 few-shot에 바로 넣으면 사용자의 최근 경험에 과적합될 수 있다. 개인정보가 포함되지 않도록 합성/일반화 예시로 바꿔 넣는 것을 원칙으로 한다.

## 오류 처리와 품질 관리

- 추출 텍스트가 부정확하면 캡쳐 JSON에 넣기 전에 사람이 수정한다.
- 화자 구분이 애매하면 해당 캡쳐는 평가 데이터셋에서 제외하거나 `notes`에 기록한다.
- 한 캡쳐 안에 너무 많은 맥락이 생략되어 판단이 어려우면 라벨을 보류한다.
- 데이터셋이 5개 미만일 때는 일치율 숫자를 성능으로 해석하지 않는다.
- 개선 후 특정 케이스는 맞고 다른 케이스가 틀어질 수 있으므로, 전체 dataset을 항상 재측정한다.

## 테스트 전략

- `learning/lib/capture.test.ts`: 캡쳐 스키마와 `captureToConversation` 변환이 기존 타입과 맞는지 확인한다.
- `learning/lib/eval-core.test.ts`: temperature 일치/거리 계산과 불일치 목록 생성을 검증한다.
- `learn:eval`: 실제 로컬 dataset으로 수동 검증한다. 이 결과 파일은 커밋하지 않는다.

## 구현 범위

이번 설계가 요구하는 구현은 작게 유지한다. 현재 `learn:eval`은 temperature exact match와 불일치 목록을 이미 출력하므로, 다음 세 가지만 보강한다.

- 기존 `learning/README.md`에 라벨 우선 루프를 더 명확히 안내한다.
- `learning/lib/eval-core.ts`와 `learning/scripts/eval.ts`에 temperature distance를 추가해 한 단계 차이와 두 단계 이상 차이를 구분한다.
- `learning/captures/example-0000.json`에 `myLabel` 예시를 추가해 새 캡쳐 작성자가 그대로 따라 쓸 수 있게 한다.
- 원본 이미지 저장, DB 저장, 사용자 데이터 수집, 파인튜닝은 하지 않는다.

## 완료 기준

- 사용자가 캡쳐 추출 텍스트를 마스킹해 `learning/captures/NNNN.json`으로 저장할 수 있다.
- 시스템 결과를 보기 전에 `myLabel`을 남길 수 있다.
- `npm run learn:eval`로 사용자 라벨과 프로그램 판단의 일치/불일치를 볼 수 있다.
- 불일치 케이스 하나를 골라 단일 변수 개선 실험으로 이어갈 수 있다.
